# Publication posture

SynthRange is published as an open research idea and reference implementation for study, critique, and adaptation. It is not a supported product, a hosted service, or a turnkey security-assessment system.

## Scope and boundaries

The repository documents an architecture for bounded AI-assisted adversarial simulation and defensive intelligence. Its material includes versioned contracts, reference components, playbooks, target adapters, and sanitized illustrative artifacts.

Readers should treat the status labels in the README as authoritative. Available source, prototypes, planned work, and architectural direction are deliberately distinguished; documented direction is not presented as operational proof.

## Source and history

This repository begins from a clean source baseline and contains only material selected for this project. It excludes local workspaces, private operational records, production data, credentials, and historical working material.

The project keeps no public release promise, support SLA, or automated zero-to-first-run deployment path. Those omissions are intentional rather than hidden product gaps.

## Security and community reporting

- Report suspected vulnerabilities through the private GitHub security-advisory route described in [SECURITY.md](../SECURITY.md); do not use public issues for vulnerability reports.
- Report conduct concerns through the private channel described in [CODE_OF_CONDUCT.md](../CODE_OF_CONDUCT.md).
- Public issues are appropriate for scoped questions, corrections, and contribution discussion.

## Maintainer publication checks

Before making a material repository change public, maintainers should:

1. review the exact tracked tree for credentials, private paths, operational records, and accidental generated artifacts;
2. run the project validation suite and inspect the hosted CI result;
3. verify that the repository's security reporting and dependency-alert settings match the published documentation;
4. preserve the distinction between research direction and implemented capability; and
5. confirm that the public history and visible files match the intended source baseline.

These checks are a publication discipline, not a claim that the project provides operational guarantees.

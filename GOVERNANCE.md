# Governance

SynthRange is a maintainer-led open research idea. This document describes how proposals are reviewed and decided; it does not commit the project to a release cadence, a support obligation, or a lifecycle guarantee.

## Principles

- Decisions optimize for a coherent, testable architecture rather than feature count.
- Architecture and public contracts require evidence, discussion, and migration paths.
- Red and Blue autonomy should remain useful; playbooks define authority, not scripts.
- Observer evidence and reproducibility come first.
- Disagreement is resolved through technical reasoning and respectful review.

## Roles

### Contributors

Anyone participating through issues, documentation, code, adapters, playbooks, testing, or review.

### Reviewers

Regular contributors trusted to review an area. Reviewers provide guidance but do not merge by default.

### Maintainers

People with repository write access who triage, review, merge, moderate, and protect project direction.

## Decisions

- Routine changes are decided through pull-request review.
- New public contracts, breaking schema changes, major dependencies, or architectural changes should begin with an issue.
- Maintainers seek rough consensus but may make a final decision when consensus is not practical.
- Important decisions should be recorded in durable repository documentation.

## Becoming a maintainer

Maintainers may invite contributors who demonstrate sustained, constructive work; sound judgment; reliable review; respect for project boundaries; and alignment with the Code of Conduct. Access can be scoped to an area before becoming repository-wide.

## Changes to governance

Governance changes use the same public review process as architecture changes. During the initial community-building phase, the repository owner is the final decision-maker.
